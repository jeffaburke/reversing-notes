We have previously used `/bin/cat` and we have looked at how it is loaded and initialized now we will look at how it is launched, reads its arguments and environment, cat runs, then it terminates.

1. Cat is launched
	- A normal ELF will call `__libc_start_main()` in `libc`. We start with the program from module 2.
	- If we do `readelf -a cat` we will see the entry point. We can look at this entry point with `objdump -d cat -M intel` specifying Intel assembly.
	- We rewrite `__libc_start_main()` and use `LD_PRELOAD` to use our custom implementation.
	  ```c
	  int __libc_start_main(
		  int *(main) (int, char * *, char * *),
		  int argc,
		  char * * ubp_av,
		  void (*init) (void),
		  void (*fini) (void),
		  void (*rtld_fini) (void),
		  void (* stack_end)
	  )
	  {
		  write(1, "Hello!\n", 7); // can also be puts
		  exit(main(arc, ubp_av, 0));
	  }
	  ```
	  ```bash
	  gcc -Wno-implicit-function-declaration -Wno-int-conversion -shared -o start_main.so start_main.c
	  ```
2. Cat reads its arguments and environment
	- At program start the only input from the outside world is the arguments. We use a custom `env` implementation as well.
	  ```c
	  int main(int argc, char **argv, char **envp)
	  {
		  for (int i = 0; envp[i] != 0; i++) puts(envp[i]);
	  }
	  ```
	  ```bash
	  gcc -Wno-implicit-function-declaration -o env env.c
	  ```
	- The `LANG` environment variable will change how the `ls` utility sorts output. `LANG=C` will sort the output via normal ASCII codes (uppercase letters first).
3. Cat does its thing
	- Using library functions
		- The binary's import symbols have to be resolved using the libraries' export symbols.
		- This in the past was an on-demand process and carried a big attack surface. In the modern day it is done when the binary is loaded and is much safer.
		- We can use `nm -D cat` to see what libraries are being pulled in. `nm -a start_main.so` will show us the exports where we can see our function exported.
	- Interacting with the environment
		- All external interaction is going to be initiated with system calls. `strace` will let us see the system calls. Syscalls are a way to invoke a command into the OS
		- Signals: Signals are a "signal" that your OS sends to your process.
			- `SIGKILL` cannot be caught nor can `SIGSTOP` which will background a process.
	- `/dev/shm` uses a shared memory mapped file.
4. Cat terminates
	- Terminates by either calling exit or an unhandled signal is received. 
	- All processes must be reaped.
