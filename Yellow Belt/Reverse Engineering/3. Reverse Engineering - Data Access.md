# Reverse Engineering - Data Access

This lecture focuses on how the access of different data in different regions looks like.

## Programs Operate on Data

Data can be in different locations.
- `.data`: Used for pre-initialized global writable data (such as global arrays with initial values)
- `.rodata`: Used for global read-only data (such as string constants)
- `.bss`: Used for uninitialized global writable data (such as global arrays without initial values)
- Stack: Used for statistically-allocated local variables.
- Heap: Used for dynamically-allocated (`malloc()`ed) variables.
## Accessing Data on the Stack

Data on the stack is accessed using:
- `push`: Store data on the "top"/left of the stack
- `pop`: Retrieve data on the "top"/left of the stack
- `rsp`-relative accesses: Offsets are positive as we are moving positively into memory to the right.
- `rbp`-relative accesses: Offsets are negative as we are moving from when things are allocated onto the stack.
- via reference
## Accessing Data in ELF Sections

Data in these sections are always at a known offset (from `rip`) from the program code. Thus they are access from `rip`-relative instructions.

## Accessing Data on the Heap

You get a pointer which is retrieved via `malloc` which is generally stored in memory on on the stack.

Notable difference between Stack Data Access and Arbitrary Data Access via a Stack Stored Reference
- Stack Data Access
  
  ```nasm
  mov rax, rsp
  mov rdx, [rax]
  ```
  
- Arbitrary Data Access via a Stack Stored Reference
  
  ```nasm
  mov rax, [rsp]
  mov rdx, [rax]
  ```
