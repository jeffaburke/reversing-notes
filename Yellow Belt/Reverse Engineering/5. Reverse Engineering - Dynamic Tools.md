# Reverse Engineering - Static Tools

## Dynamic Tools

In reverse engineering, analyzing a program at runtime.

## Program Tracing

`ltrace`: Traces library calls

`strace`: Traces system calls

Running the program with multiple different inputs might get you farther. You could look at the program with all A's then all B's and get the diff's of the outputs. 

## Debugging

`gdb` will *supposedly* become my best friend.

`cat.s`

```gas
.global _start
.global main
.intel_syntax noprefix
main:
    push rbp
    mov rbp, rsp
    sub rsp, 0x100
.read:
    mov rax, 0
    mov rdi, 0
    mov rsi, rsp
    mov rdx, 0x100
    syscall
    cmp rax, 0
    jle .ret
.write:
    mov rax, 1
    mov rdi, 1
    mov rsi, rsp
    mov rdx, 0x100
    syscall
    jmp .read
.ret:
    mov rsp, rbp
    pop rbp
    ret
_start:
    mov rdi, [rsp]
    call main
    mov rax, 60
    mov rdi, 0
    syscall
```

Compile with the following

```bash
gcc -static-pie -nostdlib -o cat.elf cat.s
```

Then open it in `gdb`.

These are recommended to put into the `.gdbinit` file.

```
set history save on
set disassembly-flavor intel
```

A basic `gdb` script for the above program.

`cat.gdb` Only works because it is `static`.

```
disp/5i $rip

break *0x401025
commands
    x/s $rsp
    printf "READ SYSCALL READ IN %d BYTES\n", $rax
    c
end
```

Can be launched with the following.

```bash
gdb -x cat.gdb cat.elf
```

## Dealing with PIE

`gdb` tries to help by loading PIE at a set base. Depending on `gdb` and kernel version it will either be at `0x555555554000` or `0x7ffff7ffc000`.

We can put our base into our `.gdbinit`  then use it in our scripts.

```
set $base = 0x7ffff7ffc000
```

Then we can modify our script

`cat-pie.gdb`

```
disp/5i $rip

break *($base + 0x1025)
commands
    x/s $rsp
    printf "READ SYSCALL READ IN %d BYTES\n", $rax
    c
end
```

```bash
gcc -static-pie -nostdlib -o cat-pie.elf cat.s
gdb -x cat-pie.gdb cat-pie.elf
```

## Timeless Debugging

Timeless debugging frees you from having to think of breakpoints ahead of time.

1. Record execution
2. Rewind Execution
3. Replay Execution

Relevant Tools:
- `gdb`: Has built-in record-replay functionality.
- `rr`: Highly performant record-replay engine.
- `qira`: Timeless debugger made for reverse engineering.

`gdb` example of Timeless debugging.

```
gdb cat.elf
record
r
c
# then say n to stop execution
```

If we `si` the program will exit but if we do `rsi` we move backwards stepping instructions. `rc` will go back to the beginning. We can then do `record stop` and we have a live program to then go forward. If we do this we should just start `record` again so we have a place to come back to.
