# Return Oriented Programming - Introduction

## Recap: The No-eXecute Bit

The shellcode module we created shellcode under different restraints, uploaded the shellcode and got the flag. In most cases we assumed that DEP/NX did not exist. But in most cases this will not work as the stack isn't executable. Shellcode is really only relevant in JIT compilation engines. The problem with these is that they are situational what if we aren't trying to break a JIT system. 

## Blast from the past: Return-to-libc

Before 64 bit architecture was a thing 32 bit arguments were passed on the stack. You could update the call to be system with a placeholder return address then pass `/bin/sh` to be run by system. 

## Code reuse in AMD64

All is not lost in 64 bit, as we can overwrite the return address and jump to different functions in the code. We can think about the binary exploitation module when we had to jump past the 1337 check. 

## Return Oriented Programming

We can chain returns one after another to achieve what registers and such we want to overwrite. Using binary code against itseld.
