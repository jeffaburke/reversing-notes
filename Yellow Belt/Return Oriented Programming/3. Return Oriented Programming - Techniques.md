# Return Oriented Programming - Techniques

## ROP Conept: Resources on the Stack

If you know where your ropchain is on the stack, you can include resources (such as `/flag` string) in your chain. If you write data onto the stack we need to make sure that it is not treated as the return address.

## ROP Concept: janitorial gadgets

Some of our gadgets will be there to simply unbreak our ropchain and that is okay.

Example: stack fix-up gadgets
```
pop r12; pop rdi; pop rsi; ret
add rsp, 0x40; ret
```

This lets us skip data on our stack.

## ROP Concept: storing values into registers

You can store values into registers using register-popping gadgets. For example: `pop rax; ret`. This will pop `rax` off the stack, then return to the next gadget with `rax` set.

## ROP Concept: rare and common gadgets

Some gadgets are rarer than others. Relatively common ones:

- `ret`: at the end of every function
- `leave; ret`: at the end of many functions (this moves `rbp` to `rsp` so we need to make sure `rbp` makes sense)
- `pop REG; ret`: restoring callee-saved registers before returning
- `mov rax, REG; ret`: setting the return value before returning

Because you can jump into the middle of an instruction, instructions don't have to be common to appear in common gadgets.

Example: every `add rsp, 0x08; ret` also contains a `add esp, 0x08; ret` if you skip the REX `H` prefix.

## ROP Concept: storing addresses into registers

This one is a bit trickier... `lea` gadgets that do what you want are rare (long instruction, and mostly used in the beginning or middle of function not near `ret`).

Alternatives:
1. `push rsp; pop rax; ret` (equivalent to `mov rax, rsp`) will get the stack address into `rax`.
2. `add rax, rsp; ret` (not perfect, but will conceptually get `rsp` into `rax`)
3. `xchg rax, rsp; ret` (swap `rax` and `rsp`. DANGEROUS)

Once we have the stack address, later gadgets can dynamically compute necessary addresses on the stack instead of having them hardcoded. Now you (might not) need a stack leak.

## ROP Concept: stack pivot

Don't like our stack? Too limiting: Try a stack pivot

```
xchng rax, rsp; ret
pop rsp; ...; ret
```

These will pivot our stack to point elsewhere. That ret will read the return address off of our new stack.

## ROP Concept: data transfer

Shellcode needs to move data around. Ropchains need to as well. One common gadget:

```
add byte [rcx], al ; pop rbp ; ret
```

This requires a gadget to set `rcx` (Which is surprisingly rare) and `rax` (less rare).

## ROP Concept: syscalls are rare

In shellcode, you use `syscall` to invoke system calls. This instruction is quite rare in normal programs (even as a part of other instructions). We may have to call library functions instead... focus on keeping it simple.

## ROP Concept: KNOW YOUR ENVIRONMENT

Our ropchain doesn't run in a vacuum, when it states there are useful addresses all over the place.
- code, stack, heap addresses in registers
- code, stack, heap addresses all over the stack

## ROP Concept: finding the rop gadgets

There are many tools available to help with this process. One example is https://github.com/zardus/ctf-tools which has installers for 3.

`rp++`

```
rp++ --unique -r2 -f /bin/bash
```

Can also try greater values than 2, but long gadgets become increasingly unstable. From here, regular expressions are our friend.

```
rp++ --unique -r2 -f /bin/bash | grep -P "(add|sub|mov) rax, r.."
```
